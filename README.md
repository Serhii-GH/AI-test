# Telegram-бот

## API для майбутнього веб-інтерфейсу

Бекенд надає endpoint `GET /api/transactions`. Він читає транзакції з PostgreSQL
та повертає JSON-масив, відсортований від найновішої до найстарішої. Кожен запис
містить ідентифікатори транзакції, користувача та категорії, назву категорії, суму,
опис і дату створення.

`GET /api/summary` повертає агреговані фінансові показники у JSON: `total_income`,
`total_expense` і `balance`. Баланс обчислюється як `total_income - total_expense`.
На поточному етапі бот додає лише витрати, тому `total_income` дорівнюватиме `0.00`
до появи функції додавання доходів.

Під час розробки API можна запустити окремо:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.api:app --reload
```

Після запуску endpoint доступний за адресою `http://localhost:8000/api/transactions`.
Docker Compose також запускає API на порту `8000` разом із ботом.

## Web dashboard

Frontend зібрано на React + Vite у папці `frontend`. У режимі розробки він
проксіює запити `/api/transactions` та `/api/summary` до backend API на
`http://localhost:8000`.

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Після цього відкрий `http://localhost:5173`. Dashboard показує картки доходу,
витрат і балансу, стовпчикову діаграму витрат за категоріями та останні операції.

## Категорії витрат

Витрати мають два рівні категорій: `Робота` та `Матеріали`, а також підкатегорію
на зразок `Електрика`, `Сантехніка` або `Малярка`. Щоб додати дохід або витрату,
надішли боту команду `/add`: він послідовно запитає тип операції, суму, основну
категорію, підкатегорію та конкретну позицію. Команда `/cancel` скасовує введення.

Після оновлення бота попередній однорядковий формат замінено покроковим введенням.
Структура збереженої операції має вигляд:

```text
Витрата → Робота → Електрика → Монтаж розетки
Дохід → Матеріали → Сантехніка → Повернення за трубу
```

Під час першого запуску нової версії застосунок одноразово видалить усі транзакції,
створені за старою однорівневою схемою. Нові транзакції після цього не видаляються.

Мінімальний Telegram-бот на `aiogram 3.x`.

## Що робить бот

Бот відповідає на команди користувача, показує меню доступних команд у Telegram і працює з токеном із локального файлу `.env`.

## Доступні команди

| Команда | Опис |
| --- | --- |
| `/start` | Вітає користувача та одразу показує можливості бота. |
| `/help` | Показує коротку довідку й перелік команд. |

## Створення `.env`

У корені проєкту створи файл `.env` і додай до нього токен свого бота:

```env
BOT_TOKEN=<токен_від_BotFather>
```

Не додавай `.env` у Git. Він уже виключений у `.gitignore` та `.dockerignore`.

## Встановлення залежностей

Потрібен Python 3.11 або новіший. У PowerShell створи віртуальне середовище й встанови залежності:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Локальний запуск

Після створення `.env` і встановлення залежностей запусти:

```powershell
.\.venv\Scripts\python.exe -m app.main
```

Щоб зупинити бота, натисни `Ctrl+C`.

## Запуск через Docker Compose

Переконайся, що Docker Desktop запущений, а `.env` є в корені проєкту. Далі виконай:

```powershell
docker compose up --build
```

Для запуску у фоновому режимі:

```powershell
docker compose up --build -d
```

Перегляд логів:

```powershell
docker compose logs -f bot
```

Зупинка контейнера:

```powershell
docker compose down
```

## Automatic restart у режимі розробки

Docker Compose монтує локальну папку `app` у контейнер. Залежність `watchdog` стежить за змінами у файлах `app/**/*.py` і перезапускає застосунок командою `python -m app.main`.

Щоб перевірити це:

1. Запусти `docker compose up --build`.
2. В окремому PowerShell відкрий логи: `docker compose logs -f bot`.
3. Зміни й збережи будь-який Python-файл у папці `app`, наприклад текст відповіді бота.
4. У логах має бути видно перезапуск процесу бота.

## Debug / Troubleshooting

Якщо бот не запускається з помилкою про `BOT_TOKEN`, перевір, що у корені проєкту є файл `.env` із рядком `BOT_TOKEN=<токен>`. Не публікуй токен у Git або в логах.

Для локального запуску використай:

```powershell
.\.venv\Scripts\python.exe -m app.main
```

Для запуску в Docker і перегляду помилок у контейнері:

```powershell
docker compose up --build
docker compose logs -f bot
```

Приклади розбору помилок зібрано у [DEBUG.md](DEBUG.md).

## Додана невелика функція

Додано команду `/help` і меню команд Telegram із `/start` та `/help`. Відповідь на `/start` тепер одразу пояснює всі доступні можливості.

## Що перевірялося після роботи AI

- Синтаксис `app/main.py` перевірено через `python -m py_compile`.
- Перевірено форматування Git через `git diff --check`.
- Перевірено, що `.env` ігнорується Git та виключений із Docker build context.
- Перевірено конфігурацію Docker Compose: передавання `.env`, монтування `app` і команда watcher.

Automatic restart потрібно перевірити під час запущеного `docker compose up --build` за кроками вище.
