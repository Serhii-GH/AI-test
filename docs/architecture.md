# Архітектура Telegram-бота

Це простий Telegram-бот на Python та бібліотеці **aiogram**. Він працює у режимі polling: програма регулярно запитує Telegram, чи надійшли нові повідомлення.

## Frontend

Frontend — це частина, яку бачить користувач. У нашому застосунку окремого сайту або мобільного інтерфейсу немає: frontend уже надає застосунок **Telegram**. Користувач вводить команди в чаті з ботом і бачить його відповіді там само.

## Backend

Backend — це код, який обробляє команди та готує відповіді. У проєкті він міститься у файлі `app/main.py`.

Там створюються бот і `Dispatcher` aiogram, а також описані обробники команд `/start` і `/help`. Токен бота завантажується зі змінної `BOT_TOKEN` у файлі `.env`.

## Database

Бази даних у поточній версії **ще немає**. Бот не зберігає користувачів, повідомлення чи інші дані: він просто одразу відповідає на отриману команду.

У майбутньому база даних знадобиться, наприклад, для профілів користувачів, історії запитів або налаштувань бота.

## API

API — це спосіб, яким програми обмінюються даними. Наш бот використовує **Telegram Bot API** через бібліотеку aiogram: отримує з Telegram повідомлення користувача та надсилає через нього відповіді.

Власного API (наприклад, окремого HTTP-сервера для інших застосунків) у проєкті **ще немає**.

## Як працює команда `/start`

1. Користувач надсилає в чаті команду `/start`.
2. Telegram передає це оновлення боту через Telegram Bot API.
3. Aiogram отримує оновлення, а `Dispatcher` визначає, що для `/start` треба викликати `start_handler`.
4. `start_handler` записує подію в лог і формує привітальне повідомлення зі списком команд.
5. Метод `message.answer(...)` надсилає відповідь назад через Telegram Bot API.
6. Telegram показує відповідь користувачеві в чаті — це і є наш frontend.

## Приклади з реальних застосунків

### Перегляд балансу в monobank

**Застосунок:** monobank.

**Функція:** перегляд балансу картки.

**Що робить користувач:** відкриває мобільний застосунок, проходить авторизацію та переглядає картку на головному екрані.

**Frontend:** мобільний застосунок показує картку, поточний баланс, валюту та інші дані у зручному інтерфейсі.

**API:** застосунок надсилає захищений запит до банківського API, щоб отримати актуальні дані картки.

**Backend:** сервер банку перевіряє, хто надіслав запит, чи має ця людина доступ до картки, і готує відповідь.

**Database:** банківська база даних зберігає інформацію про рахунки, операції та поточний баланс.

**Який результат отримує користувач:** бачить актуальний баланс своєї картки.

У роботі беруть участь усі блоки: frontend ініціює запит і показує результат, API передає дані, backend перевіряє доступ і обробляє запит, а database зберігає фінансові дані.

### Побудова маршруту в Google Maps

**Застосунок:** Google Maps.

**Функція:** побудова маршруту до потрібного місця.

**Що робить користувач:** вказує пункт призначення, за потреби — точку відправлення та тип транспорту, а потім натискає кнопку побудови маршруту.

**Frontend:** застосунок або сайт показує карту, поле пошуку, варіанти маршрутів, відстань і час у дорозі.

**API:** клієнт надсилає запит із координатами та обраним типом пересування до сервісів карт і маршрутів.

**Backend:** сервери обробляють запит, порівнюють можливі шляхи, враховують дані про дороги, рух транспорту та обраний транспорт.

**Database:** бази даних містять карти, дороги, адреси, географічні об'єкти та іншу інформацію, потрібну для пошуку шляху.

**Який результат отримує користувач:** отримує один або кілька маршрутів на карті з орієнтовним часом і відстанню.

У роботі беруть участь усі блоки: frontend збирає параметри та малює маршрут, API передає запит і відповідь, backend обчислює маршрут, database надає географічні дані.

### Перегляд відео на YouTube

**Застосунок:** YouTube.

**Функція:** перегляд відео.

**Що робить користувач:** відкриває сторінку відео та натискає кнопку відтворення.

**Frontend:** сайт або мобільний застосунок показує відеоплеєр, назву, опис, кнопки керування та рекомендації.

**API:** клієнт запитує дані про відео та адресу для його потокового завантаження; під час перегляду надсилає технічні події, наприклад про початок або зупинку відтворення.

**Backend:** сервери перевіряють доступність відео для користувача, добирають якість потоку та організовують передавання відеоданих.

**Database:** бази даних зберігають назву, опис, автора, налаштування доступу, коментарі та інші метадані. Самі великі відеофайли зазвичай зберігаються в окремому файловому або хмарному сховищі.

**Який результат отримує користувач:** відео починає відтворюватися, а користувач може керувати переглядом.

У роботі беруть участь усі блоки: frontend відтворює відео, API обмінюється командами й даними, backend керує перевірками та передаванням, database зберігає метадані, а сховище надає сам відеофайл.
